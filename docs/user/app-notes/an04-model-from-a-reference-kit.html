AN-04 — A nonlinear FET model from a reference kit

A transistor that already has a model in another simulator's design kit can become a ComposedFET by sampling that model and fitting what it gives. Which runs to make in the source simulator, which plane to sample at and how to get there, what each Model Composer step does with the result, and how to check the model against the kit it came from.

When this note applies

A transistor often already has a good model: the one in a foundry's or a vendor's design kit, written for another simulator. That model can be the reference for a circuitRF model. Sample it the way a lab would measure a device, hand the samples to Model Composer, and the result is a .cmodel that a schematic places as a ComposedFET and that DC, S-parameters, harmonic balance and loadpull all use.

Sampled data is better than measured data in three ways, and the flow below is built around all three:

  • It is noise-free and as dense as you like. A grid of every 0.1 V costs seconds, not a week on a probe station.
  • It can be taken where no instrument can reach: at the core's own terminals, inside the pads, inductances and resistances, and with self-heating switched off.
  • It can be repeated at will, so the same benches can be run on the kit and on the fitted model and the two compared point for point.

The work that takes longest is not the fit. It is deciding what to export from the source simulator and getting it out in a form the composer reads. Most of this note is about that.

The flow

Two kinds of run come out of the source simulator, and they have different jobs:

Runs Become Used for
DC I–V, small-signal Y or S at every DC bias, at one or more temperatures One SimulatedTables data set Fitting the currents and the charges
Power sweeps, two-tone sweeps, loadpull LargeSignal data sets Validation only — never fitted

Keeping the large-signal runs out of the fit is what makes them a fair test: the model has never seen them.

What to run in the source simulator

Use one test bench per run, with the kit's transistor at the size you want as the base, and nothing else in it but bias and ports.

Run Analysis Sweep What to save
I–V DC Vgs inside Vds, inside temperature when there are several Vgs, Vds and the gate and drain currents at every point
Small-signal S-parameters at every bias of the DC sweep One low frequency for the charges (a few hundred MHz to 1 GHz); add a span only if the network is to be checked Y (or S) of the two-port, gate port 1, drain port 2, source grounded
Capacitances (optional) The core's operating-point capacitances, where the simulator reports them The same bias grid cgs, cgd, cds and optionally cm, or the matrix C
Large-signal (for validation) Harmonic balance: power sweep at the operating bias; loadpull at the frequencies you care about Drive up into compression The power sweep as a CSV; the loadpull as a file the composer reads (.spl, .lpcwave or a CSV)

Ranges. Sample wider than the circuit will ever go: from 2 V below pinch-off to well into forward gate conduction, and from 0 V (or slightly negative) to beyond the peak drain swing. A model is continued linearly past the edge of its data, and that continuation is not the device. Sampled points cost nothing; the bias table gives the steps.

Settings in the source simulator. Three matter, and each one gives a model that looks right at the operating point and is wrong elsewhere when it is missed:

  • Self-heating off for every fitting run — the kit's thermal resistance set to zero, or its thermal switch off. The composer fits isothermal currents, at the temperature of each run, and adds the heating itself on the Thermal step. Data that already contains heating would be heated twice.
  • Traps and dispersion off, unless you mean to model them. A DC sweep with them on and a small-signal analysis with them frozen describe two different devices.
  • Stay inside the kit's valid range. Many kit models clamp their inputs outside it, and the clamped region samples as flat data that the fit then reproduces faithfully.

Temperature. Run the DC and small-signal sweeps at two or more temperatures, spanning the junction temperatures the circuit will reach under drive (the ambient plus the heating). The model then takes T as an input, follows the run's temp, and self-heating becomes available.

Choosing the plane, and the negative network

The composer always fits the core: the intrinsic gate, drain and source, inside the pads, inductances and series resistances. A kit device is that core wrapped in its own extrinsic network, and the samples can be taken on either side of it.

Plane How to sample In the composer
Intrinsic — preferred Record the core's internal node voltages, if the kit exposes them; or wrap the kit device in its negative network, as drawn ReferencePlane=intrinsic. The network holds the kit's values, all locked; nothing is fitted to it
Device Sample at the kit device's terminals, as it is ReferencePlane=device, with a six-pin network holding the kit's values, locked; the composer removes it

Why intrinsic is preferred. At the intrinsic plane the points lie exactly on the grid you swept, and the network plays no part in the fit: it is exported with the core exactly as the kit has it. At the device plane the composer removes the network with a DC solve carrying the sampled currents, so the intrinsic points move off the grid and every Table constituent must re-grid them. Either way the network values come from the kit, not from a fit: a fit can only find values the data can tell apart, and the kit already knows them.

Building the negative network. Take the kit's extrinsic network from its model card or documentation and draw it again in the source simulator's bench, between each port and the kit device's terminal:

  • Read it from the core outwards. What sits next to the core in the kit sits next to the port in the copy. For a two-shell network — pad capacitance, inductance, inner capacitance, resistance, from the terminal in — the copy is −R, −Cinner, −L, −Cpad, from the port in.
  • Negate every value, the mutuals included. A source resistance and inductance that both loops share go in the source lead, negated, in the same place.
  • Use it in DC and small-signal analyses only. Negative elements are exact in a linear analysis and make the bench non-passive, so they have no place in harmonic balance or a transient. The large-signal validation runs use the kit device as it is.
  • At DC only the resistances matter. The −R cancels the kit's own drop, so the core sees exactly the port's voltage, and the I–V grid you sweep is the intrinsic grid.
  • A value that depends on temperature must be negated at each temperature you run.

If the kit's network values are not published, sample at the device plane instead and let the Network step fit them cold-FET and multi-bias. That needs S over a frequency span, and the two cold biases (Vds = 0 V, pinched off and with the gate forward-biased).

Writing the tables

The composer reads a simulator's tables most easily as a MATLAB .mat file, written by MATLAB, or by Python with scipy.io.savemat. Name the arrays as you like; the import maps them. The bias arrays are either the two axes of a Vgs × Vds grid, or one value per point. With several temperatures, write one value per point, with a T array beside them:

import numpy as np, scipy.io as sio
# Swept as vgs (nG,), vds (nD,) in V and T (nT,) in degC; id, ig (nG, nD, nT) in A, positive into the terminal;
# freq (nF,) in Hz; Y (nG, nD, nT, nF, 2, 2) in S. Flattened to one value per point, in the same order:
G, D, TT = np.meshgrid(vgs, vds, T, indexing="ij")
sio.savemat("kit_tables.mat", {"vgs": G.ravel(), "vds": D.ravel(), "T": TT.ravel(),
                               "id": id.ravel(), "ig": ig.ravel(), "freq": freq,
                               "Y": Y.reshape(-1, len(freq), 2, 2)})

At one temperature, vgs and vds can stay the grid's axes, with id shaped (nG, nD), and AmbientC states the temperature. Every array, its unit and its shape are in File formats. The things that go wrong:

  • Signs. Currents are positive into the terminal. A simulator that reports the drain current flowing out gives a model with negative transconductance.
  • The port order. Gate is port 1, drain port 2, source grounded.
  • The base size. Note the kit device's finger count and unit gate width: they become N0 and W0, and every instance scales from them (Periphery scaling). Sample at a size from the middle of the range you will use.

In Model Composer, step by step

Tools ▸ Model Composer…, choose Active, and import the .mat on the Data step as Simulated tables. The steps then run in order; for kit data some of them have nothing to do.

Step For kit data
Data Import the tables as Simulated tables: map each array, and state ReferencePlane and, for a single temperature, AmbientC. Import each large-signal run as Large signal. Set N0 and W0 to the sampled device's.
Pads None. A simulated device has no probe pads.
Network Pick a stock network or open a six-pin .csch of the kit's own, type the kit's values, and lock every one. Set each value's scaling rule. With every value locked, the fit holds them.
Current Id and Ig. The ANN default suits most kits; see below when it does not.
Charge Qg and Qd, from Y, or from the capacitance table if that is what you saved. The default trains an ANN on the capacitances alone.
Thermal Turn self-heating on and type the kit's Rth and Cth (or its thermal ladder), since the data was sampled isothermal. Extraction needs pulsed data that a kit does not give.
Traps None, unless the kit models them and you sampled them as the reference describes.
Check Check Charge Conservation. A kit's own charges can fail it; the model's must pass.
Validate Run all. Each large-signal set is compared at its own bench (below).
Export Writes the .cmodel. VA writes the same model as Verilog-A source for another simulator.

When the defaults are not enough

The defaults are chosen for a measured device over an ordinary bias range: a two-layer network of 8 tanh neurons per constituent, and a relative weighting floored at 10 % of the largest current. A kit sampled over a wide range — deep pinch-off to forward conduction, several temperatures, tens of thousands of points — asks more of a fit than that. Look at the fit before changing anything:

  • The status line after a fit gives each constituent's held-out error and its training domain, e.g. Id: ANN 2×8 · held-out 0.8 % · domain 412 pts. A held-out error well above the training error means the network is too small or under-trained for the data.
  • The Error tab on the Current step maps model minus data over the bias plane. An error concentrated in one corner — subthreshold, the knee, the hot end — says which lever to pull.
  • The Gm and Gds tabs compare the data's own derivatives with the model's. Harmonic balance runs on the derivatives, so a current that fits in value and not in slope still drives badly.

Then, one lever at a time:

Symptom Try
Held-out error high everywhere A larger network on the method picker (more neurons, or a third layer), more iterations, or more restarts on the step
Subthreshold current poor Lower the drain-current weighting floor, IdFloor in the document's current settings (File formats), so small currents count for more
The knee or the hot end poor More points there in the source simulator; a sampled grid can always be made finer
Every ANN size leaves a residual A Table constituent: on dense simulated data it follows the samples by construction
An equation template does not fit Expected over a wide range: the templates are for compact, few-parameter models. Use an ANN or a Table

Table re-gridding. A Table constituent samples a smooth function of the points onto its grid and fits a spline to that. The function is an ANN trained on the points by default, or a radial-basis interpolant (RBF) through them. The RBF solves one dense system over every point: its memory grows with the square of the point count and its time with the cube. It suits a few thousand points; for the tens of thousands a dense kit sweep gives, re-grid through the ANN, or write the table directly (below).

Checking the model against the kit

The validation is only as fair as the benches on the two sides are equal. A difference in the bench reads as a difference in the model.

  • The same bench, both sides. The same bias, the same source and load terminations at every harmonic, the same frequency and drive plan, the same compression point. Show testbench on the Validate step writes each item's .cnl, and the Model Validation Report names its benches in testbenches/, so the circuitRF side is on record.
  • The same thermal state. Validate with self-heating on in both simulators, at the kit's own thermal resistance. The isothermal data trained the core; the validation tests the model as a designer will use it.
  • A loadpull at compression, not drive by drive. The Validate step compares each load at the same gain compression (3 dB by default), so a model that compresses a little earlier is not marked wrong at every drive level.
  • Loads near the edge of stability. A load at which the source simulator's drive-up does not converge, or turns back on itself, is a statement about that load, not about either model. Leave it out of both sides or run both at a source impedance that keeps the input passive.
  • Bias S at the terminals. Place the exported model and the kit device side by side in one S-parameter bench at a few biases. The core was fitted inside the network; this checks the two together.

When a comparison disagrees, the dashed loop in the flow goes back into the composer — a step's settings, a network value, Rth — not back to the source simulator, unless the data itself was short.

Writing the .cmodel directly

A .cmodel is an open format, and every constituent the composer writes can also be written by a script: Writing a .cmodel. For gridded intrinsic tables this is a real alternative to fitting. A Table constituent is a tensor-product cubic spline on a grid of sites, so the samples themselves, on the grid they were taken on, are the table: no network to train, no re-grid. The network, the scaling rules and the thermal model go in the same file, and circuitrf check reads it back.

The composer remains the place to check such a model. circuitrf model validate kit.cmc --model kit.cmodel compares it with a document's data exactly as the Validate step compares a fitted one, and circuitrf model check-charge on a .cnl that places it checks its charges.

The same flow headless

Every step is a circuitrf model noun, the same functions the window calls (Model Composer in the CLI):

circuitrf model new kit.cmc --kind active --network gan-two-shell --fingers 4 --unit-width "125 um"
circuitrf model import kit.cmc kit_tables.mat --as SimulatedTables --map vgs=vgs --map vds=vds --map T=T --map id=id --map ig=ig --map freq=freq --map Y=Y --condition ReferencePlane=intrinsic
circuitrf model fit kit.cmc --step all
circuitrf model check-charge kit.cmc
circuitrf model validate kit.cmc
circuitrf model export kit.cmc -o kit.cmodel
circuitrf model export kit.cmc -o kit.va

The network's values and locks are part of the .cmc, which is JSON (File formats); type them in the window's Values table, or write them into the document, before fit.

Checklist

  • Self-heating off and traps off in every fitting run; the temperatures span the junction temperatures the circuit reaches.
  • The I–V grid runs from below pinch-off into forward gate conduction and past the peak drain swing.
  • Y or S at every DC bias, at a low frequency for the charges.
  • The plane is stated: intrinsic through the kit's internal nodes or its negative network, or device with the kit's network in the composer.
  • The kit's network values are typed and locked, each with its scaling rule.
  • Currents are positive into the terminal; gate is port 1, drain port 2.
  • N0 and W0 are the sampled device's.
  • The kit's Rth and Cth are typed on the Thermal step.
  • Large-signal runs are imported as Large signal, for validation only, and both simulators run the same benches.
